# Learnings and verification

## Initial source findings

- Current source contains 345 operation records, including three aliases, and
  330 distinct generated command paths before this change.
- There are 23 noun/verb groups spanning API generations and 11 command paths
  with multiple scoped routes. These sets overlap.
- Generated files must be regenerated, not manually modified.
- The current binary and the older verification reference are not identical to
  the current source inventory. Live comparison evidence must name the binary.
- `apns-csr list` is a POST despite its CLI verb; it is not a read-only test.
- `seamless upload` supports APPLE, LINUX, and WINDOWS.
- Provisioning profile APIs explicitly describe iOS distribution.
- `.claude/commands/esper.md` is generated by `go run ./tools/skillgen`.
- Contract checks compare generated endpoint metadata to canonical specs; CLI
  naming changes should not silently change endpoint meaning or inputs.

## Live comparisons

Completed 32 unique live GET invocations covering 18 comparisons. The comparison
script reused responses within the batch rather than repeating overlapping
commands. Thirty succeeded, and two legacy item reads returned HTTP 404 while
their v1 counterparts succeeded. Exact arguments, binary SHA-256, timing, exit
codes, sanitized stderr, and response shapes are in `comparisons.jsonl`.

The binary was built from the unmodified current source into the approved
temporary directory, rather than replacing the user's installed CLI. Raw payloads
were held only in memory. The evidence contains no response values from user,
device, app-download, or credential fields.

Normalized installation-list contracts are identical after resolving schema
references and ignoring descriptions/examples. Both live responses contained the
same complete two-record collection. Event-feed contracts, by contrast, differ in
pagination defaults and required response fields; sample equality is insufficient.

Baseline tests passed: `go test ./tools/codegen ./tools/contractcheck ./internal/cmd/...`.

## Implementation and checks

- Added public-command regression tests first and observed the expected failures
  for the missing iOS names, retained legacy installation command, and help text.
- Added a small shared command policy consumed by code generation and contract
  checking. Original API nouns, paths, payloads, flags, and approval behavior stay
  intact. The existing alias mechanism excludes the retired legacy endpoint from
  executable commands and generated documentation.
- Updated HTTP golden tests to use the renamed commands and retained assertions
  for request methods, routes, scopes, query parameters, bodies, API errors, and
  validation failures. The installation replacement has a regression check for
  canonical resolution and input-contract drift.
- Regenerated operation metadata and the `/esper` command document with the Go
  generators. A second generation produced identical SHA-256 hashes for both.
- Compared every generated operation against `HEAD`: exactly 13 records changed,
  with changes limited to `Command` and the one replacement's `AliasOf`. All
  345 endpoint records remain represented; 341 are executable and four are alias
  metadata. Twelve routes use iOS-prefixed commands.
- Corrected one derived comparison count without another API call: a response
  containing `count: 0` and `results: null` has zero rows, not one envelope row.
  The evidence record includes this correction, and the comparison helper now
  handles nullable empty collections. Request timings and results are unchanged.

Live evidence remains the original 32 GET calls and 18 comparisons. No API writes
or new approvals were needed. No live batch was replayed after the naming change.
The comparison script captures the pre-change command layout; its existing-output
guard prevents accidentally overwriting or replaying this historical batch.
